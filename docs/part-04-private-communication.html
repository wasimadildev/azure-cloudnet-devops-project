07 Backend security

Allow only
frontend → API.

Now create the backend security boundary. The rule allows the entire frontend subnet to reach only TCP 8080 on the backend.

Source10.10.1.0/24frontend subnet
PortTCP 8080API service
Destination10.10.2.0/24backend subnet
ALLOW
Azure CLI / nsg-backend
az network nsg create \
  --resource-group rg-cloudnet-prod \
  --name nsg-backend \
  --location centralindia

az network nsg rule create \
  --resource-group rg-cloudnet-prod \
  --nsg-name nsg-backend \
  --name Allow-Frontend-To-Backend-8080 \
  --priority 100 \
  --source-address-prefixes 10.10.1.0/24 \
  --destination-address-prefixes 10.10.2.0/24 \
  --destination-port-ranges 8080 \
  --protocol Tcp \
  --access Allow \
  --direction Inbound

az network vnet subnet update \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-backend \
  --network-security-group nsg-backend
The default inbound deny continues to reject Internet → backend TCP 8080.
08 Effective policy

Three tiers,
three boundaries.

The application path should grow inward. Each layer accepts only the traffic required by the layer behind it.

FRONTENDnsg-frontendInternet → 80 / 443Your IP → 22
BACKENDnsg-backend10.10.1.0/24 → 8080Internet → 8080 denied
DATABASEnsg-database10.10.2.0/24 → 5432Internet → 5432 denied
Internet → Frontend 80 / 443→ Frontend → Backend 8080→ Backend → Database 5432

Connection refused vs timeout

A refused connection often means the host answered but no service is listening. A timeout can indicate filtering, routing, or a silent service.
