01 Why NAT

Outbound is not
inbound.

The backend may need package updates, GitHub APIs, public registries, or external APIs. NAT Gateway lets it initiate those connections while keeping unsolicited Internet traffic out.

INBOUND

Internet → VM

Internet Public IP vm-web-01

Someone on the Internet initiates the connection. NSGs decide whether it is allowed.

OUTBOUND

VM → Internet

vm-api-01 NAT github.com

The private VM initiates the request. NAT supplies the public source identity.

↗

NAT Gateway is outbound connectivity, not inbound publishing. Return traffic belongs to the outbound flow; random Internet users cannot initiate a new connection through it.

02 SNAT

Translate the
source address.

Private addresses such as 10.10.2.4 cannot be used as Internet source addresses. NAT Gateway performs source network address translation with its public IP.

Before NAT10.10.2.4:54321private source
SNATNAT Gatewaynat-cloudnet-backend
After NAT20.x.x.x:54321public source
Destination stays the same

The external server sees the NAT public IP, while the VM keeps its private IP inside Azure.

03 CloudNet design

Private subnet,
controlled exit.

Associate the NAT Gateway with snet-backend. Every eligible private workload in that subnet can use the configured outbound IP.

snet-backend10.10.2.0/24vm-api-01 / private

Once associated with the subnet and attached to a public IP, NAT Gateway provides the outbound Internet path. It is not a route-table entry.

04 Build sequence

Create the
outbound path.

Create a Standard static public IP, create the NAT Gateway, attach the IP, and associate the backend subnet.

  1. 01

    Create the NAT public IP

    Open Public IP addresses → Create. Use pip-nat-cloudnet, IPv4, Standard SKU, Static assignment, the same region, and rg-cloudnet-prod.

    Why static?External APIs can allowlist one predictable egress address.
  2. 02

    Create the NAT Gateway

    Open NAT gateways → Create. Name it nat-cloudnet-backend, use the same region and resource group, and choose StandardV2.

  3. 03

    Attach outbound IP

    In the outbound IP settings, select pip-nat-cloudnet.

  4. 04

    Associate the backend subnet

    Select vnet-cloudnet-prod and snet-backend, then review and create.

Azure CLI / NAT Gateway
az network public-ip create \
  --resource-group rg-cloudnet-prod \
  --name pip-nat-cloudnet \
  --location centralindia \
  --sku Standard \
  --allocation-method Static

az network nat gateway create \
  --resource-group rg-cloudnet-prod \
  --name nat-cloudnet-backend \
  --location centralindia \
  --public-ip-addresses pip-nat-cloudnet \
  --sku StandardV2

az network vnet subnet update \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-backend \
  --nat-gateway nat-cloudnet-backend
Azure CLI parameters can vary with CLI version. Run az network nat gateway create --help if your installed version differs.

07 Responsibilities

Four tools,
four questions.

Keep the network mental model clean. Each Azure capability answers a different question.

RoutingWHERE?Chooses the next hop.
NSGALLOWED?Filters traffic.
NAT GatewayHOW OUT?Provides public egress.
DNSWHO?Maps names to IPs.
Routing warning

A UDR for 0.0.0.0/0 to a virtual appliance or gateway can override NAT Gateway's direct Internet path. Add broad routes only when the firewall path is real.

08 Advanced note

Outbound scale
has a limit.

Every outbound connection needs a source-port translation. NAT Gateway provides a large SNAT port pool and can scale with additional public IPs or prefixes.
