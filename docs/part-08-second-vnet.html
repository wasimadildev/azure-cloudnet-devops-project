04 Build sequence

Create the
development VNet.

Build the VNet and four subnets without adding VMs yet. The objective is a clean network boundary ready for Part 09.

  1. 01

    Create the VNet

    Open Virtual networks → Create. Use resource group rg-cloudnet-prod, name vnet-cloudnet-dev, the same region, and IPv4 address space 10.20.0.0/16.

  2. 02

    Add the frontend subnet

    Create snet-frontend-dev with address range 10.20.1.0/24.

  3. 03

    Add the backend subnet

    Create snet-backend-dev with address range 10.20.2.0/24.

  4. 04

    Add database and management

    Create snet-database-dev at 10.20.3.0/24 and snet-management-dev at 10.20.10.0/24. Stop here: no peering yet.

Azure CLI / development VNet
az network vnet create \
  --resource-group rg-cloudnet-prod \
  --name vnet-cloudnet-dev \
  --location centralindia \
  --address-prefix 10.20.0.0/16

az network vnet subnet create \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-dev \
  --name snet-frontend-dev \
  --address-prefixes 10.20.1.0/24

az network vnet subnet create \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-dev \
  --name snet-backend-dev \
  --address-prefixes 10.20.2.0/24

az network vnet subnet create \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-dev \
  --name snet-database-dev \

az network vnet subnet create \

06 Isolation

Separate means
separate.

Before peering exists, a production VM cannot use a development private address. The networks are intentionally independent.

Production10.10.1.4
NO PEERINGisolatedPart 09 will connect them
Development10.20.1.4
Key idea

Creating two VNets does not connect them. VNet peering is a separate relationship with its own configuration and routing behavior.

07 Peering preparation

Build the pair
before the bridge.

Part 09 will create two peering links: production to development and development to production. Both sides must be configured.

VNet Avnet-cloudnet-prod10.10.0.0/16peering: prod-to-dev
Part 09VNet peering
VNet Bvnet-cloudnet-dev10.20.0.0/16peering: dev-to-prod
!

Do not use overlapping address space. Once networks overlap, peering and predictable routing become impossible without redesign.
