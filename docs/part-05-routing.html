01 Core distinction

Routing says
where. NSG says
whether.

A route chooses the next hop for a destination. An NSG then evaluates whether the traffic is allowed to reach the resource and port.

ROUTING

Where should traffic go?

10.10.2.4Virtual networkBackend
VS
NSG

Is traffic permitted?

10.10.1.4TCP 8080?ALLOW / DROP
!

Both can be correct and the connection can still fail. A valid route does not override an NSG denial, and an allow rule cannot help if traffic is sent to the wrong next hop.

06 User-defined route

Add a route
without breaking traffic.

Create rt-backend, associate it with the backend subnet, and add a deliberately isolated lab route for 10.30.0.0/16.

  1. 01

    Create the route table

    Open Route tables → Create. Use resource group rg-cloudnet-prod, name rt-backend, and the same region as the VNet.

  2. 02

    Add the safe lab route

    Create lab-route-example with destination 10.30.0.0/16, next hop type Virtual appliance, and next hop IP 10.10.10.4.

    ImportantNo appliance exists at this address yet. Inspect the configuration, but do not expect connectivity.
  3. 03

    Associate the backend subnet

    Open rt-backend → Subnets → Associate, then select vnet-cloudnet-prod and snet-backend.

  4. 04

    Do not add a default route

    Never point 0.0.0.0/0 at a nonexistent appliance. A broad route can break VM outbound connectivity.

Azure CLI / rt-backend
az network route-table create \
  --resource-group rg-cloudnet-prod \
  --name rt-backend \
  --location centralindia

az network route-table route create \
  --resource-group rg-cloudnet-prod \
  --route-table-name rt-backend \
  --name lab-route-example \
  --address-prefix 10.30.0.0/16 \
  --next-hop-type VirtualAppliance \
  --next-hop-ip-address 10.10.10.4

az network vnet subnet update \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-backend \
  --route-table rt-backend
The lab route demonstrates UDR configuration. Remove it after inspection if you do not need it.
07 Route selection

Specific beats
broad.

When multiple routes match, networking uses the longest prefix match. A /24 is more specific than a /16.

Route A / broad10.10.0.0/16Virtual network
Destination10.10.2.50matches both
Route B / specific10.10.2.0/24Virtual appliance
Winner10.10.2.0/24

The /24 route is more specific, so it can direct traffic differently from the broader /16 route.
