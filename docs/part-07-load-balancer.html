01 Why load balance

One endpoint.
Multiple servers.

A single API VM is a single failure point. A Load Balancer gives clients one frontend IP and distributes TCP/UDP flows across healthy backend instances.

BEFORE

One backend

Internet vm-api-01

If API-01 fails, the application path fails.

→
AFTER

Healthy pool

Load Balancer API-01API-02

If one instance fails, new flows can use the healthy instance.

↗

Layer 4, not Layer 7. Azure Load Balancer distributes TCP/UDP flows. Application Gateway later handles HTTP host, path, TLS, and WAF decisions.

04 Health endpoint

Make health
observable.

Both API VMs must answer /health with HTTP 200. The probe checks the application path, not just whether the VM is powered on.

from http.server import BaseHTTPRequestHandler, HTTPServer class Handler(BaseHTTPRequestHandler): def do_GET(self): body = b"API-01 HEALTHY" if self.server.name == "api-01" else b"API-02 HEALTHY" if self.path == "/health": self.send_response(200) else: self.send_response(200) body = b"Hello from the API" self.end_headers() self.wfile.write(body) server = HTTPServer(("0.0.0.0", 8080), Handler) server.name = "api-01" # change to api-02 on vm-api-02 server.serve_forever()

05 Load Balancer

Connect the
load balancer.

Use a Standard public Load Balancer with a static frontend IP, backend pool, HTTP probe, and TCP rule.

  1. 01

    Create the public IP

    Create pip-lb-cloudnet as IPv4, Standard SKU, Static assignment, in rg-cloudnet-prod.

  2. 02

    Create the Load Balancer

    Create public Standard Load Balancer lb-cloudnet-prod and select pip-lb-cloudnet as its frontend IP configuration.

  3. 03

    Create the backend pool

    Add pool pool-api, select vnet-cloudnet-prod, and add vm-api-01 and vm-api-02.

  4. 04

    Create the health probe

    Use HTTP, port 8080, path /health, interval 5 seconds, unhealthy threshold 2.

  5. 05

    Create the balancing rule

    Use frontend port 8080, backend port 8080, protocol TCP, pool pool-api, and probe probe-api-health.

06 NSG integration

Let the probe
reach the pool.

Health probes originate from the Azure Load Balancer service. Allow the AzureLoadBalancer service tag to reach TCP 8080 on the backend.

SourceAzureLoadBalancerservice tag
DestinationTCP 8080backend API
ActionALLOWpriority 100 or unused
Backend NSG / probe rule
az network nsg rule create \
  --resource-group rg-cloudnet-prod \
  --nsg-name nsg-backend \
  --name Allow-AzureLoadBalancer-8080 \
  --priority 110 \
  --source-address-prefixes AzureLoadBalancer \
  --destination-port-ranges 8080 \
  --protocol Tcp \
  --access Allow \
  --direction Inbound
!

Client traffic is separate from probe traffic. The probe must be healthy, and the actual public application flow must also be permitted by the backend security design.
