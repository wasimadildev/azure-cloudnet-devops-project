03 Address plan

Address space is
architecture.

The VNet reserves a large /16 range. Each /24 subnet gets a clean, non-overlapping slice so future peering and routing remain possible.

04 Build sequence

Create the
foundation.

Use the Portal to see each resource clearly, or switch to CLI to practice the repeatable DevOps workflow.

  1. 01

    Create the resource group

    Open Resource groups in the Azure Portal and select Create. Use rg-cloudnet-prod, choose your preferred region, then review and create.

    RegionKeep future lab resources in the same region where possible.
  2. 02

    Create the virtual network

    Open Virtual networks → Create. Select the resource group, name it vnet-cloudnet-prod, and set the IPv4 address space to 10.10.0.0/16.

    Address spaceDo not use overlapping ranges with future hub, dev, or test VNets.
  3. 03

    Add four subnets

    Open the VNet, choose Subnets, and add each range from the address plan: frontend, backend, database, and management.

    Subnet ruleEvery subnet must sit inside the VNet and must not overlap another subnet.
  4. 04

    Review the result

    Open the VNet overview and confirm the four subnets exist with the exact names and CIDR ranges. Stop here: no VM is required for this part.

  --resource-group rg-cloudnet-prod \
  --name vnet-cloudnet-prod \
  --address-prefix 10.10.0.0/16

az network vnet subnet create \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-frontend \
  --address-prefixes 10.10.1.0/24

az network vnet subnet create \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-backend \
  --address-prefixes 10.10.2.0/24

  --resource-group rg-cloudnet-prod \

Commands are ready for a region named eastus. Replace it with your chosen Azure region.
