01 Why gateway

One web edge,
many decisions.

Application Gateway is a Layer 7 reverse proxy. It understands HTTP and HTTPS requests, unlike the Layer 4 Load Balancer from Part 07.

LOAD BALANCER / L4

Flow distribution

TCP / UDPfrontend port → backend port

Routes connections without inspecting HTTP paths or hostnames.

APPLICATION GATEWAY / L7

Request routing

Host / path / TLS/api → API, / → web

Terminates TLS, probes HTTP, routes requests, and can attach WAF.

↗

Production direction: Internet traffic terminates at the gateway. Backend VMs become private targets instead of public application endpoints.

02 Gateway subnet

Reserve a subnet
for the gateway.

Application Gateway requires a dedicated subnet. Do not place VMs or unrelated resources in it.

Create snet-appgateway before the gateway. Keep the range reserved for future scale and gateway instances.

04 Build sequence

Create the
application edge.

Build the gateway in the dedicated subnet, then add a public frontend IP, listener, backend pool, HTTP settings, probe, and rule.

  1. 01

    Create the dedicated subnet

    In vnet-cloudnet-prod, create snet-appgateway with 10.10.20.0/24. Keep it dedicated.

  2. 02

    Create Application Gateway

    Open Application gateways → Create. Use appgw-cloudnet-prod, Standard_v2 or WAF_v2, the same region, and the dedicated subnet.

  3. 03

    Configure frontend and listener

    Attach a Standard static public IP, create an HTTPS listener on port 443, and use a certificate for real TLS deployments. HTTP port 80 may redirect to HTTPS.

  4. 04

    Add backend and settings

    Add the web/API private targets, create HTTP settings for the backend port, and configure a health probe such as /health.

  5. 05

    Attach the routing rule

    Connect the listener, HTTP settings, backend pool, and probe. Test the public gateway hostname or IP only after the backend is healthy.

07 WAF direction

Put policy at
the edge.

WAF_v2 adds managed web protection to the gateway. Enable it after the basic routing path works so network and application policy remain easy to diagnose.

01Gateway workslistener and backend healthy
02WAF policy attachedmanaged rule sets
03Public app protectededge filtering + routing
!

WAF is not a substitute for NSGs. WAF filters web requests; NSGs still protect subnet and NIC traffic boundaries.
