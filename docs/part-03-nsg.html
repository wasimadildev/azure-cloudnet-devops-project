01 Security model

Filter traffic
where it enters.

An NSG is a stateful set of rules evaluated against source, destination, port, protocol, direction, priority, and action.

Part 03 scope. We secure the frontend path first. Backend and database NSGs will later use private subnet sources instead of Internet-wide rules.

02 Association

Subnet or NIC?
Know the boundary.

An NSG can be associated with a subnet, a NIC, or both. This lab begins with the subnet so every supported interface in the frontend segment receives the same baseline policy.

Subnet level
snet-frontendnsg-frontend

One policy for resources in the subnet. This is the association used in this part.

NIC level
vm-web-01 / NICnsg-web-01

Resource-specific policy. Useful when one interface needs an exception.

Both
Subnet NSGNIC NSG

Rules from both levels apply. Plan the combined result carefully.

Practical rule

Start with subnet-level policy for shared boundaries. Add NIC rules only when the exception is intentional and documented.

04 Evaluation

Lower number
speaks first.

NSG rules are evaluated by priority. A lower number has higher priority, so an allow at 100 is evaluated before a deny at 200.

100Allow SSHTCP 22 / My IPALLOW
200Allow HTTPTCP 80 / InternetALLOW
210Allow HTTPSTCP 443 / InternetALLOW
65000+DenyAllInBoundunmatched inboundDENY
↗

Default rules already include DenyAllInBound. Do not add a redundant “deny everything” rule for this lab. Let the Azure default handle unmatched inbound traffic.

05 Build sequence

Create
nsg-frontend.

Create the NSG in the same resource group and region as the VNet, then associate it with the frontend subnet.

  1. 01

    Create the network security group

    Open Network security groups → Create. Use resource group rg-cloudnet-prod, name nsg-frontend, and the same region as the VNet.

  2. 02

    Associate the subnet

    Open nsg-frontend → Subnets → Associate. Select vnet-cloudnet-prod and snet-frontend.

    AssociationSubnet-level policy for the frontend boundary.
  3. 03

    Add only the required inbound rules

    Add SSH from your IP only at priority 100, HTTP from Internet at 200, and HTTPS from Internet at 210.

  4. 04

    Leave unmatched traffic denied

    Azure's default DenyAllInBound catches ports such as 8080 unless you explicitly add an allow rule.

Azure CLI / nsg-frontend
az network nsg create \
  --resource-group rg-cloudnet-prod \
  --name nsg-frontend \
  --location centralindia

az network nsg rule create \
  --resource-group rg-cloudnet-prod \
  --nsg-name nsg-frontend \
  --name Allow-SSH-MyIP \
  --priority 100 \
  --source-address-prefixes <YOUR_PUBLIC_IP>/32 \
  --destination-port-ranges 22 \
  --protocol Tcp \
  --access Allow \
  --direction Inbound

az network nsg rule create \
  --resource-group rg-cloudnet-prod \
  --nsg-name nsg-frontend \
  --name Allow-HTTP \
  --priority 200 \
  --source-address-prefixes Internet \
  --destination-port-ranges 80 \
  --protocol Tcp \
  --access Allow \
  --direction Inbound

az network nsg rule create \
  --resource-group rg-cloudnet-prod \
  --nsg-name nsg-frontend \
  --name Allow-HTTPS \
  --priority 210 \
  --source-address-prefixes Internet \
  --destination-port-ranges 443 \
  --protocol Tcp \
  --access Allow \
  --direction Inbound

az network vnet subnet update \
  --resource-group rg-cloudnet-prod \
  --vnet-name vnet-cloudnet-prod \
  --name snet-frontend \
  --network-security-group nsg-frontend
Replace <YOUR_PUBLIC_IP> with your current public IPv4 address. Use a /32 host prefix.

07 Practical tests

Break it
on purpose.

A security rule becomes real when you test both the permitted path and a port that has no allow rule.

01 / allowed

SSH from your IP

ssh azureuser@<PUBLIC_IP>

Should work when the source matches the Allow-SSH-MyIP rule.

02 / allowed

HTTP on port 80

sudo apt install nginx -y

Start Nginx, then open http://<PUBLIC_IP> in your browser.

03 / blocked

Unlisted port 8080

curl http://<PUBLIC_IP>:8080

Should fail because no inbound rule allows TCP 8080.

09 Architecture

NSG is a filter,
not the whole firewall.

NSGs provide subnet or NIC-level stateful filtering. Azure Firewall is a separate centralized control for inspection, network and application rules, logging, and shared policy.

NSGSubnet / NIC traffic filterlocal boundary · priority rules · stateful
+
Azure FirewallCentralized security serviceinspection · policy · logging · routing
Final direction

Application Gateway + WAF → Azure Firewall → NSGs → frontend → backend → database.
